## Diagnóstico actual

El frontend ya contiene una portada y una pantalla de registro de paquetes. El registro incluye captura manual, lectura de QR desde imagen o cámara, validación local, catálogos dependientes, datos simulados y estados de carga, error y éxito. Su contrato de API sigue marcado como provisional y el backend no expone controladores de paquetes, catálogos, autenticación, rutas o notificaciones; solo expone el controlador raíz. La navegación actual usa un estado local `home | register`, no un router, y no existe sesión ni navegación por rol.

Por tanto, el frontend puede avanzar ahora con estructura, componentes de presentación, contratos tipados y datos simulados. La integración real y el cierre de cada módulo dependen de los contratos y controles de autorización del backend.

## Paso actual

### Paso 2 — Contrato de navegación, sesión y roles

**Por qué:** todas las nuevas páginas dependen de una navegación estable y de conocer la identidad y el rol del usuario. Construirlas antes dejaría permisos y redirecciones duplicados en cada feature.

**Debe aplicar Santiago:**

1. Acordar con `AUTH-01` cómo inicia y termina la sesión, cómo se obtiene el usuario actual y cómo se representa cada rol.
2. Elegir e instalar el router mediante Docker Compose y declarar las rutas propuestas en el mapa.
3. Crear el shell privado con encabezado, navegación por rol, salida de sesión y contenedor responsive.
4. Añadir límites de ruta para usuario no autenticado y sin permiso, recordando que el backend valida la autorización real.

**Archivos esperados:**

- `frontend/src/app/router.tsx`
- `frontend/src/features/auth/`
- `frontend/src/shared/layout/`
- `frontend/src/shared/auth/`

**Lote mecánico disponible para Codex:** crear el esqueleto de carpetas, registrar rutas ya acordadas y mover la pantalla existente a una ruta sin alterar su lógica, cuando el usuario lo solicite explícitamente.

**Verificación:**

```text
docker compose exec frontend npm run test
docker compose exec frontend npm run build
docker compose exec frontend npm run lint
```

Comprobar manualmente: usuario no autenticado va a login; cada rol ve solo su navegación; una URL sin permiso muestra la vista 403; recargar una URL conserva la pantalla.

**Criterio de salida:** el equipo ha publicado el contrato mínimo de autenticación y la aplicación tiene rutas estables y un shell por rol, sin depender del selector local de `App.tsx`.
